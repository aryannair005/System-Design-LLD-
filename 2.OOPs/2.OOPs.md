# Object-Oriented Programming (OOP) in Java

## 1. History of OOP

Before Object-Oriented Programming (OOP), many programs were written using procedural programming, where code was organized around functions and procedures.

As software applications became larger, developers faced problems such as:

- **Code repetition:** The same logic was written multiple times.
- **Difficult maintenance:** Changing shared logic in multiple places was error-prone.
- **Poor organization:** Data and the functions operating on it were often separate.
- **Limited reusability:** Reusing existing code across different parts of an application could be difficult.

OOP emerged to help organize complex software by combining data and related behavior into objects.

### Evolution of OOP

- **1960s — Simula:** Introduced important OOP concepts such as classes and objects.
- **1970s — Smalltalk:** Helped develop and popularize object-oriented programming.
- **1990s — Java:** Made OOP widely accessible to application developers through its class-based programming model.

### Why Do We Need OOP?

OOP helps us:

1. Reduce code duplication through reuse and shared behavior.
2. Organize code into classes and objects.
3. Protect data through encapsulation.
4. Extend existing functionality without rewriting everything.
5. Make large applications easier to maintain and test.

**Example:** Suppose a college application manages students, teachers, and administrators. Instead of writing separate copies of common person-related logic, we can create reusable classes and share common behavior where appropriate.

## 2. What Is OOP?

**Object-Oriented Programming (OOP)** is a programming paradigm that organizes software around objects, which combine data (attributes) and behavior (methods).

### Class vs Object

- **Class:** A blueprint that defines the properties and behaviors of a type of object.
- **Object:** An instance of a class with its own state.

### Java Example

```java
class Student {
    String name;
    int age;

    void study() {
        System.out.println(name + " is studying");
    }
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();

        s1.name = "Aryan";
        s1.age = 22;

        s1.study();
    }
}
```

Here, `Student` is a class, `s1` is a reference to a newly created `Student` object, and `name` and `age` represent its state.

## 3. The Four Pillars of OOP

The four pillars are:

1. Encapsulation
2. Abstraction
3. Inheritance
4. Polymorphism

## 3.1 Encapsulation

**Definition:** Encapsulation is the process of bundling data and the methods that operate on it into a class, while controlling access to the internal state.

It helps protect data from invalid or unauthorized modifications.

### Java Example

```java
class BankAccount {
    private double balance;

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();

        account.deposit(1000);
        System.out.println(account.getBalance());
    }
}
```

**Output:**

```text
1000.0
```

### Key Points

- `private` prevents direct access to `balance` from outside the class.
- `deposit()` validates the amount before changing the balance.
- `getBalance()` provides controlled access to the balance.

**Real-world example:** You deposit money into a bank account through an authorized operation rather than directly editing the bank's stored balance.

## 3.2 Abstraction

**Definition:** Abstraction means exposing essential functionality while hiding unnecessary implementation details.

It focuses on **what an object does**, rather than how it performs the operation internally.

In Java, abstraction can be achieved using abstract classes and interfaces.

### Java Example

```java
interface Payment {
    void pay(double amount);
}

class UpiPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount + " using UPI");
    }
}

public class Main {
    public static void main(String[] args) {
        Payment payment = new UpiPayment();
        payment.pay(500);
    }
}
```

**Output:**

```text
Paid 500.0 using UPI
```

### Key Points

- `Payment` defines what a payment implementation must provide.
- `UpiPayment` defines how the payment operation works.
- The calling code can use the `Payment` interface without depending on its internal implementation.

**Real-world example:** You use an ATM to withdraw money without needing to understand the bank's internal transaction processing.

## 3.3 Inheritance

**Definition:** Inheritance allows one class to acquire accessible properties and behaviors from another class.

It supports code reuse and establishes an **is-a relationship**.

### Java Example

```java
class Animal {
    void eat() {
        System.out.println("Animal is eating");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog is barking");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog dog = new Dog();

        dog.eat();
        dog.bark();
    }
}
```

**Output:**

```text
Animal is eating
Dog is barking
```

### Key Points

- `Animal` is the parent (superclass).
- `Dog` is the child (subclass).
- `extends` establishes class inheritance in Java.
- `Dog` inherits the accessible `eat()` method, so it does not need to redefine it.

**Real-world example:** A dog is an animal, so it can share common animal behavior while also having its own specific behavior.

**Important:** Java supports single inheritance of classes, but a class can implement multiple interfaces.

## 3.4 Polymorphism

**Definition:** Polymorphism means "many forms." It allows the same method name or interface to represent different behaviors depending on the context.

Java supports two commonly discussed forms of polymorphism:

- **Compile-time polymorphism:** Method overloading.
- **Runtime polymorphism:** Method overriding and dynamic method dispatch.

### A. Compile-Time Polymorphism — Overloading

The same class contains methods with the same name but different parameter lists.

```java
class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

The compiler selects the appropriate method based on the arguments.

### B. Runtime Polymorphism — Overriding

A subclass provides its own implementation of an inherited method.

```java
class Animal {
    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal a1 = new Dog();
        Animal a2 = new Cat();

        a1.sound();
        a2.sound();
    }
}
```

**Output:**

```text
Dog barks
Cat meows
```

### Key Points

- Both variables use the parent type `Animal`.
- The actual objects are `Dog` and `Cat`.
- At runtime, Java invokes the overridden method belonging to the actual object's class.

**Real-world example:** Different payment methods can expose the same `pay()` operation while performing the payment differently.

## 4. Difference Between the Four Pillars

| Pillar        | Main purpose                                                    | Java mechanism                            |
| ------------- | --------------------------------------------------------------- | ----------------------------------------- |
| Encapsulation | Protect and control access to internal state                    | Access modifiers, private fields, methods |
| Abstraction   | Hide implementation details                                     | Interfaces, abstract classes              |
| Inheritance   | Reuse and extend existing class behavior                        | `extends`                                 |
| Polymorphism  | Allow different implementations through a common method or type | Overloading, overriding                   |

## 5. Quick Revision

- **OOP:** Organizes software around objects containing state and behavior.
- **Encapsulation:** Controls access to data and bundles it with related behavior.
- **Abstraction:** Exposes essential functionality while hiding implementation details.
- **Inheritance:** Enables a class to inherit accessible behavior from another class.
- **Polymorphism:** Allows the same method or common type to represent different behaviors.
- **Why OOP?** It helps manage complexity, improve maintainability, and reuse code.

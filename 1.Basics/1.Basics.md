# Introduction to Low-Level Design (LLD)

## 1. What is LLD?

**Low-Level Design (LLD)** is the process of designing the internal structure of a software application, including its classes, objects, methods, interfaces, and their relationships.

It explains how individual components of an application will be implemented and interact with each other.

**Example:** For a parking lot application, LLD defines classes such as `ParkingLot`, `Vehicle`, `ParkingSpot`, and `Ticket`, along with their attributes, methods, and relationships.

### Three Main Goals of LLD

1. **Scalability**
   - The application should be designed so it can handle more users or work in the future without making major changes to its existing structure.
   - Example: Adding new types of parking spots without redesigning the entire parking system.

2. **Maintainability**
   - The code should be easy to understand, debug, modify, and extend.
   - Example: Updating the parking fee calculation without changing unrelated parts of the application.

3. **Reusability**
   - Components should be designed so they can be reused in different parts of the application or in other applications.
   - Example: Reusing a common payment interface for different payment methods, such as UPI and credit cards.

## 2. What is HLD?

**High-Level Design (HLD)** focuses on the overall architecture of a software application and how its major components communicate with each other.

It defines the system's major building blocks, databases, services, APIs, communication mechanisms, and deployment architecture.

**Example:** For a parking lot application, HLD defines the frontend, backend service, database, payment service, and how these components communicate.

### Key Focus of HLD

- Overall system architecture
- Major components and their interactions
- Database and technology choices
- APIs and communication between services
- Scalability, availability, and reliability at the system level

## 3. What is DSA?

**Data Structures and Algorithms (DSA)** focuses on organizing data efficiently and designing algorithms to solve computational problems.

It helps us choose appropriate data structures and optimize the time and space required to solve a problem.

**Example:** Using a queue to manage vehicles waiting for parking spots or a hash map to look up parking tickets efficiently.

### Key Focus of DSA

- Data structures such as arrays, linked lists, stacks, queues, trees, graphs, and hash maps
- Algorithms such as sorting, searching, graph traversal, and dynamic programming
- Time complexity and space complexity
- Efficient problem-solving

## 4. Difference Between HLD, LLD, and DSA

| Aspect         | HLD                                         | LLD                                                           | DSA                                                    |
| -------------- | ------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------ |
| Full form      | High-Level Design                           | Low-Level Design                                              | Data Structures and Algorithms                         |
| Main focus     | Overall system architecture                 | Internal code structure                                       | Efficient problem-solving                              |
| Answers        | How is the whole system organized?          | How should individual components be designed and implemented? | How can a computational problem be solved efficiently? |
| Main elements  | Services, databases, APIs, infrastructure   | Classes, objects, methods, interfaces, design patterns        | Data structures, algorithms, complexity                |
| Typical output | Architecture diagram                        | Class diagram, UML diagram, code                              | Algorithm or working solution                          |
| Example        | Designing a food delivery system's services | Designing `Restaurant`, `Order`, and `Payment` classes        | Finding the shortest route between two locations       |

## 5. How HLD, LLD, and DSA Work Together

Consider building an online food delivery application.

1. **HLD:** Decide the major components, such as user service, restaurant service, order service, payment service, and database.
2. **LLD:** Design classes such as `Order`, `Restaurant`, `Customer`, and `Payment`, including their methods and relationships.
3. **DSA:** Choose suitable data structures and algorithms for tasks such as searching restaurants, matching orders, and finding optimal delivery routes.

All three are important, but they solve different problems. DSA can be used within the components designed through LLD, which are part of the overall architecture defined through HLD.

## 6. Quick Revision

- **LLD:** Designs the internal structure of the code, focusing on maintainability, reusability, and extensibility.
- **HLD:** Designs the overall architecture and interactions between major system components.
- **DSA:** Focuses on solving computational problems efficiently using appropriate data structures and algorithms.
- **Remember:** HLD = system architecture, LLD = code structure, DSA = algorithmic efficiency.
